# 架构

## 组件

| # | 组件 | 职责 | 可见性 |
|---|---|---|---|
| 1 | IM 适配层 | 接收群消息、鉴权、把结果发回群 | 私有 |
| 2 | 指令解析 | 从消息里取出玩家名、处理帮助/空参数 | 私有 |
| 3 | 身份服务客户端 | 名字 → `uuid` + 标签信息 | 私有（第三方服务） |
| 4 | 战绩客户端 | `uuid` → Hypixel 玩家数据，带降级 | 私有 |
| 5 | 解析层 | 原始 JSON → 扁平字段字典 | 契约公开 |
| 6 | 渲染层 | 字段字典 → JPEG 卡片 | 私有 |
| 7 | 资源与缓存 | 素材、临时文件、短期结果缓存 | 私有 |

组件 5 与 6 之间只通过 `docs/api-contract.md` 描述的字典通信：
换渲染风格不需要动数据代码，换数据源也不需要动渲染代码。

## 缓存与限流

- **UUID 复用**：名字 → `uuid` 的结果长期缓存，避免重复请求身份服务。
- **战绩缓存**：同一 `uuid` 在短窗口内（分钟级）不重复请求上游，直接复用上次结果。
- **用户冷却**：同一用户连续查询有冷却，防止刷屏把上游打爆。
- **无后台任务**：没有定时轮询、没有排行榜抓取；没人查询就没有请求。
- **不做历史**：不落库、不对比前后两次数据，因此不构成会话/历史追踪。

## 降级策略

战绩源按顺序尝试，任一成功即停止：

1. **官方接口**（配置了 key 时才尝试）——数据最新，是正常路径。
2. **只读缓存源**（免 key）——仅在官方路径失败/无 key 时使用，用于保证卡片可用。

两条路径都失败时，不返回半成品卡片，而是回一条明确的文字提示，
并指出"key 可能已过期"，便于维护者处理。

## 错误处理约定

| 上游结果 | 面向用户 | 面向日志 |
|---|---|---|
| 404 查无此人 | 明确提示名字/UUID 可能有误 | info |
| 401 / 403 key 失效 | 提示维护者更新 key | warn（含降级动作） |
| 429 限流 | 提示稍后再试 | warn |
| 超时 / 网络错误 | 提示稍后再试 | warn |
| 渲染异常 | 不回图，回报渲染失败 | error |

原则：用户看到的是人话，不是堆栈；堆栈只进日志。

## 资源与清理

渲染产物写入临时文件后发送，发送完成数秒后删除，避免长期堆积。
素材（底图、贴图、字体、头像渲染依赖）随部署环境提供，不入库、不公开分发。
