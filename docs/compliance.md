# 与 Hypixel API 政策对齐的检查清单

依据：Hypixel Developer Dashboard 的 API Policy（内容会更新，以官方页面为准）。
本清单用于自查，不是官方文件。

## 必须满足

- [x] **项目在 Developer Dashboard 注册**，用 Personal 申请即可（非商业化、非团队）。
- [x] **API key 只在服务端**：存于部署环境的私有配置，不进仓库、不下发客户端、不写进日志。
- [x] **不做代理**：不把 Hypixel 接口转发给第三方开发者，不提供"输入任意端点即转发"的公共入口。
      （用户触发一次查询、服务端代为请求，属于正常应用行为；对外转发接口才是被禁止的。）
- [x] **不做会话/历史追踪**：只展示当前值，不落库、不做"今日涨了多少"这类统计。
- [x] **不做大规模自动采集**：没有后台轮询、没有定时爬取，请求由用户命令驱动。
- [x] **合理缓存**：战绩本地缓存 10 分钟（`stats_cache_ttl`）、每人 60 秒冷却（`cmd_cooldown`）、
      皮肤与头像缓存 10 分钟。同一玩家在缓存窗口内重复查询，对 Hypixel 的请求数为 0。
- [x] **第三方辅助源只作兜底**：核心战绩始终优先取自 Hypixel 官方端点；仅在官方 key 缺失/失效时
      回落到只读公共缓存，且不对外转发、不再分发任何端点。
- [x] **不泄露被 Nick 隐藏的玩家**：不尝试反匿名。
- [x] **不侵犯商标**：项目明确声明与 Hypixel 无关联、未获背书。
- [x] **不用多 key 绕限额**：单一项目单一应用；key 轮换只用于替换失效 key。

## 明确不要做

- ❌ 把 key 填进任何公开网站、公开表格、公开仓库或前端代码。
- ❌ 让用户自带"我的 key"来共用你这一个服务（这属于共享 key 的变体）。
      要支持多实例，应该让每个实例自己注册应用、用自己的 key。
- ❌ 承诺"实时刷新"或对外宣传高频轮询。
- ❌ 以"给其他人/其他项目用"为理由申请 key。
- ❌ 在申请文案里出现 proxy / mirror / redistribute / session tracking 这类表述。

## 保活注意事项

- 官方会清理**长期无请求**的应用（约 14 天 / 28 天两个观察窗口），
  所以即使只有自己用，也要保持周期性使用。
- 开发（Development）key 有效期很短（约 3 天）；**应用审核通过后**才会拿到
  有效期明显更长的 key。因此"长期可用"这件事取决于应用是否过审，而不是 key 怎么生成。
- 重度长期使用开发 key 可能被视为滥用，正式项目应当走应用申请。
