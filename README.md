# Hypixel 起床战争 · 群内查询机器人（文档仓库）

> 本仓库**只有文档**。
> 机器人插件本体、卡片渲染器、字体、背景素材、第三方服务配置均为**私有组件，不在本仓库内**，
> 也不接受关于它们的实现提问。

## 这是什么

一个跑在社区群聊里的查询机器人：群成员用一条命令，把自己（或群里提到的某位玩家）的
**Hypixel 起床战争（Bed Wars）**战绩渲染成一张图片卡片发回群里。

- 输入：`/tag <玩家名>`（不带参数 = 查配置里的默认账号）
- 输出：一张 1024×768 的战绩卡片图片
- 定位：社区自助查询工具，不是统计网站，也不对外提供接口

## 数据流

```
群成员 ──"/tag <玩家名>"──▶ IM 机器人（私有插件）
                              │
                              ├─ 1 ─▶ 黑名单数据源（第三方，私有配置）
                              │        返回 uuid + 该玩家的标签信息
                              │
                              ├─ 2 ─▶ 战绩源：优先 Hypixel 官方 /v2/player
                              │        key 只在服务端；失败时回退到只读缓存源
                              │
                              ├─ 3 ─▶ 解析层：stats.Bedwars → 卡片字段
                              │
                              ├─ 4 ─▶ 渲染层（私有）：底图轮换 → 半透明面板
                              │        → MC 字体/段位色 → 3D 头像 → JPEG
                              │
                              └─ 5 ─▶ 图片回群；临时文件 5 秒后删除
```

### 每一步在做什么

1. **指令解析**：从群消息里取出玩家名；空参数走默认账号。
2. **身份与标签**：向第三方黑名单数据服务查这个名字，拿到 `uuid` 和标签信息，
   顺带完成"查无此人 / 未收录"的判定。
3. **战绩抓取**：用 `uuid` 请求 Hypixel 官方玩家接口，只读 `stats.Bedwars` 与
   `achievements.bedwars_level`。官方 key 无效或缺失时，降级到只读缓存源，
   保证卡片不会因为 key 过期就整体不可用。
4. **解析**：把嵌套的 Bedwars 字段摊平成一层（击杀/死亡/终杀/终死/FKDR/KDR/
   胜负/胜率/床/资源/各模式 FKDR/段位色），缺失字段一律补 0，不编造数据。
5. **渲染**：合成卡片图片。背景在数张 MC 方块贴图之间轮换，浅灰半透明面板保证
   小字对比度，段位色跟随 Hypixel 的段位字段，头像是 3D 等轴测。
6. **回图**：图片直接发回群，临时文件延时删除。

## 常见问题

**为什么不用现成的免 key 公共 API？**
曾经最常用的那类免 key Hypixel 镜像（例如 Slothpixel）已经停服，其他几家要么删掉了
Hypixel 路由，要么长期 404。更关键的是：Hypixel 的 API 政策明确禁止"把 Public API
代理给第三方开发者"、禁止共享 key，所以这类公共镜像天然活不长。想要稳定数据，
唯一的办法是申请自己的 key。

**为什么不做"实时刷新"?**
Hypixel 政策要求项目尽量缓存、不做大规模自动采集，也不允许用它做会话级/历史追踪。
本项目是"用户问一次、查一次、回一张图"，没有后台轮询，也不存历史。

**为什么降级到缓存源而不是报错？**
key 有有效期，社区用户不该因为维护者 key 过期就完全看不到卡片。降级源只读、
且仅在官方请求失败时使用，代价是数据可能略旧。
